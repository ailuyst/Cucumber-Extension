# Publishing Guide

This guide describes the release workflow for the Cucumber Runner VS Code extension. It is operational documentation only: do not publish until all `TODO_*` placeholders are replaced and the release checklist passes.

## 1. Create a Visual Studio Marketplace Publisher

1. Sign in to https://marketplace.visualstudio.com/manage.
2. Create a publisher.
3. Choose a stable publisher id. This must replace `todo-publisher` in `package.json`.
4. Update any docs and tests that mention the extension id:
   - `package.json` `publisher`
   - `test/integration/suite/index.js`
   - documentation references to `TODO_PUBLISHER`

Use a publisher id that can remain stable long term. Changing it later effectively changes the extension identity.

## 2. Create a Personal Access Token

1. Open Azure DevOps user settings.
2. Create a Personal Access Token.
3. Scope: Marketplace `Manage`.
4. Store it in a password manager.
5. Do not commit the token to the repository.

## 3. Install vsce

The project already uses local `@vscode/vsce`, so prefer:

```powershell
npm install
npm run package
```

If you want a global CLI:

```powershell
npm install -g @vscode/vsce
```

## 4. Login

After replacing `TODO_PUBLISHER`:

```powershell
npx vsce login TODO_PUBLISHER
```

Paste the Marketplace PAT when prompted.

## 5. Test Before Publishing

Run the release checks:

```powershell
npm run compile
npm run test:parser
npm run test:details
npm run test:integration
npm run bundle
npm run deps:check
npm run package
```

Then manually test the extension through F5 using `docs/manual-test.md` and `docs/release-checklist.md`.

## 6. Install a Local VSIX

After `npm run package`, install the generated VSIX:

```powershell
code --install-extension cucumber-runner-0.0.1.vsix
```

The project script is:

```powershell
npm run publish:vsix
```

If the version changes, update the VSIX filename in that script before using it.

## 7. Publish the 0.0.1 Preview

Replace:

- `TODO_PUBLISHER`
- `TODO_REPOSITORY_URL`
- `TODO_ICON`, if an icon is added
- `TODO_SCREENSHOT`, if screenshots are added

Package first:

```powershell
npm run package
```

Publish as pre-release:

```powershell
npm run publish:preview
```

The script runs:

```powershell
vsce publish --pre-release
```

Do not run this until the publisher id and repository URL are real.

## 8. Update Version

For a patch release:

```powershell
npm run version:patch
```

For a minor release:

```powershell
npm run version:minor
```

Then update:

- `CHANGELOG.md`
- `RELEASE_NOTES.md`
- release checklist results
- any version-specific docs

Package and test again before publishing.

## 9. Publish an Update

1. Update version and release notes.
2. Run all checks.
3. Run `npm run package`.
4. Install the VSIX locally and test manually.
5. Run `npm run publish:preview` for another preview release.
6. For a stable release later, use `npx vsce publish` without `--pre-release`.

## 10. Unpublish or Deprecate

Use unpublish only for serious mistakes. Prefer publishing a fixed version when possible.

```powershell
npx vsce unpublish TODO_PUBLISHER.cucumber-runner
```

If the extension should remain visible but users should move away from it, update the README and Marketplace description with a deprecation notice, then publish a final version.

## 11. Publishing Safety Rules

- Never publish with placeholder publisher or repository values.
- Never publish without running the manual F5 checklist.
- Never publish if `npm run package` includes `src/`, `test/`, `sample-workspace/`, or sourcemaps in the VSIX.
- Keep the Marketplace token out of source control.
- Keep `dist/extension.js` generated by the release build, not manually edited.
